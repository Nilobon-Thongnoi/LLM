=== QUESTION ===
(20 คะแนน) จงออกแบบอัลกอริทึมจากโจทย์ดังต่อไปนี้
หนึ่งในอาการของผู้ป่วยโควิดคือจะมีอุณหภูมิร่างกายที่สูงกว่าคนปกติ สมมติว่าทางมหาวิทยาลัยมีแนวคิดจะซื้อกล้องตรวจวัดอุณหภูมิที่สามารถวัดอุณหภูมิของคนได้ทีละหลาย ๆ คนพร้อมกัน

ให้ n เป็นจำนวนคนที่เดินผ่านหน้ากล้อง ให้นักศึกษาออกแบบอัลกอริทึมสำหรับตรวจหาผู้ป่วยโควิด ซึ่งใช้เวลาในการทำงานน้อยกว่า O(n) ในคำตอบของนักศึกษาให้อธิบายขั้นตอนการทำงานของอัลกอริทึมโดยละเอียด โดยในคำตอบให้ระบุ
• วิธีการเปรียบเทียบเพื่อหาผู้ป่วย
• วิเคราะห์ประสิทธิภาพการทำงานของอัลกอริทึมดังกล่าวโดยแสดงวิธีการหาพร้อมคำอธิบายโดยละเอียด

=== REFERENCE_ANSWERS ===
CONSTANT FEVER_THRESHOLD = 37.5
CONSTANT FRAME_WIDTH, FRAME_HEIGHT

FUNCTION DetectFeverPeople(thermalCamera):
    infectedList = []

    WHILE camera is running:
        frame = thermalCamera.captureFrame()
        hotRegions = ScanFrameParallel(frame)

        FOR EACH region IN hotRegions:
            personID = IdentifyPerson(region)
            infectedList.APPEND(personID)
            AlertSecurity(personID, region.temperature)

    RETURN infectedList


FUNCTION ScanFrameParallel(frame):
    hotPixelMask = PARALLEL_MAP(frame, PIXEL =>
        RETURN (PIXEL.temperature >= FEVER_THRESHOLD)
    )                                          // ทำพร้อมกันทุกพิกเซล -> O(1) เชิงเวลา

    hotRegions = ConnectedComponentLabeling(hotPixelMask)
    RETURN hotRegions   // list ของกลุ่มพิกเซลที่ร้อนเกิน threshold


FUNCTION IdentifyPerson(region):
    RETURN TrackAndMatch(region.boundingBox)

วิธีการเปรียบเทียบเพื่อหาผู้ป่วย:
1. กล้องจับภาพความร้อนทั้งเฟรม (resolution คงที่ เช่น 640×480) โดยไม่สนใจว่าเฟรมนั้นมีคนกี่คน
2. ใช้ hardware/GPU ประมวลผลแบบขนาน (parallel/SIMD) เปรียบเทียบค่าอุณหภูมิของทุกพิกเซลกับค่า threshold (เช่น 37.5°C) พร้อมกันในครั้งเดียว แทนที่จะวนลูปตรวจทีละคน
3. พิกเซลที่อุณหภูมิเกิน threshold จะถูก group เป็นก้อน (blob) ด้วยการประมวลผลภาพ ระบุตำแหน่งคนที่มีไข้ในเฟรมนั้น

วิเคราะห์ประสิทธิภาพ:
- ถ้าตรวจทีละคนแบบ sequential จะได้ O(n)
- แต่เนื่องจากกล้องจับภาพทั้งเฟรมที่มีขนาดพิกเซลคงที่ (ไม่ขึ้นกับ n) และประมวลผลแบบขนานในระดับฮาร์ดแวร์ การวิเคราะห์ 1 เฟรม (ซึ่งอาจมีคนอยู่กี่คนก็ได้) ใช้เวลาคงที่ O(1) ต่อเฟรม
- เมื่อ n คนเดินผ่านกล้องภายในเวลาที่ใกล้เคียงกัน (อยู่ในเฟรมเดียวกันหรือไม่กี่เฟรม) จำนวนเฟรมที่ต้องประมวลผลไม่ได้เพิ่มเป็นสัดส่วนโดยตรงกับ n จึงทำให้ความซับซ้อนโดยรวมน้อยกว่า O(n) (เข้าใกล้ O(1) หรือ O(n/k) เมื่อ k คือจำนวนคนเฉลี่ยต่อเฟรม)

=== RULES ===
- คำตอบมี 3 ส่วน: Pseudocode / คำอธิบาย / วิเคราะห์ประสิทธิภาพ
  - Pseudocode เป็นหลักฐานหลักของ a3 และของ Big-O ที่แท้จริง (c3) ไม่ต้องตรง syntax ภาษาใด
  - คำอธิบาย เป็นหลักฐานหลักของ a1 (ข้อสมมติ) และ a2 (วิธีเปรียบเทียบ)
  - วิเคราะห์ประสิทธิภาพ เป็นหลักฐานหลักของ c1 และ c2
  - ถ้าส่วนใดขัดกับ Pseudocode ให้ตัดสิน Big-O จาก Pseudocode และระบุใน feedback ว่าไม่สอดคล้องกัน
- threshold ใดก็ได้ในช่วงไข้ที่สมเหตุสมผล (เช่น 37.5 หรือ 38 องศา) ถือว่าถูก
- วิเคราะห์ตามกรณีแย่ที่สุด (worst case) ถ้านักศึกษาบอกเองว่ากรณีแย่ที่สุดเป็น O(n) หรือสูงกว่า ให้เข้ากฎเพดาน
- การประมวลผลขนาน: ดูจากคำตอบว่าใช้ processor กี่ตัว และต้องรวมผลหรือไม่ แล้วใช้ตารางนี้ตัดสิน (อย่านำตัวเลขในตารางไปปนกับสิ่งที่นักศึกษาเขียน)
  | จำนวน processor ที่นักศึกษาระบุ | ต้องรวมผลไหม | เวลาที่ถูก | ต่ำกว่า O(n)? |
  | n ตัว (ตัวละ 1 คน) | ไม่ต้อง: แต่ละตัวเขียนผลของคนนั้นเอง | O(1) | ใช่ |
  | n ตัว (ตัวละ 1 คน) | ต้อง: นับจำนวน หรือหาค่าสูงสุด แบบต้นไม้ | O(log n) | ใช่ |
  | sqrt(n) ตัว | ตัวละ sqrt(n) คน | O(sqrt n) | ใช่ |
  | p ตัว (ตัวแปร) | รวมผลแบบต้นไม้ | O(n/p + log p) | ใช่ เมื่อ p โตตาม n |
  | จำนวนคงที่ไม่ขึ้นกับ n (เช่น 2 ตัว) | - | O(n) | ไม่ใช่ เข้ากฎเพดาน |
  - ใช้ processor n ตัว ถือเป็นข้อสมมติที่ระบุชัดแล้ว (a1 ได้เต็มถ้าตรรกะถูก) ไม่ต้องพิสูจน์ว่าสมจริง
  - ถ้าอ้าง O(1) หรือ O(log n) จากการขนาน แต่ไม่บอกว่าใช้ processor กี่ตัว หรือไม่แสดงที่มา ให้ c2 ไม่เกิน 2
  - การแยก "เวลา O(1)" กับ "งานรวม O(n)" ถือเป็นการวิเคราะห์ที่ละเอียด ไม่หักคะแนน และงานรวม O(n) ไม่ทำให้เข้ากฎเพดาน
- การเปรียบเทียบทีละกลุ่มด้วยคำสั่งเดียว (SIMD) ที่ขนาดกลุ่มคงที่ ยังเป็น O(n) เข้ากฎเพดาน
- คำสั่งเดียวที่ตรวจทุกค่า (เช่น "If All Temperature >= 38") โดยไม่ระบุ hardware ขนาน ยังต้องตรวจทุกคน เป็น O(n)
- อัลกอริทึมที่ตรวจหาผู้ป่วยไม่ถูกต้อง เช่น ตรวจแค่ครึ่งเดียวทิ้งที่เหลือ, ใช้ค่าเฉลี่ยแทนรายคน ให้ a1 = 0 แม้ Big-O จะต่ำกว่า O(n)
- กฎเพดาน: ถ้าอัลกอริทึมที่เขียนจริงต้องไล่ตรวจทุกคน (O(n) หรือสูงกว่า เช่น วนลูปทุกคน, sort ก่อน) ให้ a1 = 0 และ c3 = 0 ส่วน a2, a3, c1, c2 ให้ตามปกติ
- แนวทางที่ยอมรับ (ไม่ต้องเหมือนเฉลย) เมื่อระบุข้อสมมติชัดเจน:
  - ประมวลผลภาพทั้งเฟรมแบบขนาน (แนวเฉลย) โดยสมมติว่ามี hardware ประมวลผลพร้อมกัน
  - binary search บนรายการอุณหภูมิที่เรียงไว้แล้ว โดยสมมติว่ากล้องส่งข้อมูลมาแบบเรียงแล้ว (ถ้านับเวลา sort ด้วย จะเป็น O(n log n) เข้ากฎเพดาน)
  - heap ที่กล้องดูแลไว้แล้ว ตรวจ root เพื่อดูว่ามีคนเกิน threshold ไหม
- ถ้าต้องรายงานผู้ป่วยทุกคน เวลาเพิ่มอีก O(k) เมื่อ k = จำนวนผู้ป่วย คำตอบแบบ O(log n + k) หรือ O(1 + k) ถือว่าถูก
- divide and conquer หาค่าสูงสุดแบบ T(n) = 2T(n/2) + O(1) ได้ O(n) ไม่ใช่ O(log n) ถ้านักศึกษาสรุปว่า O(log n) ให้ c3 = 0
- a1 (4): 4 = วิธีถูกและระบุข้อสมมติ, 2 = วิธีถูกแต่ไม่ระบุข้อสมมติ (เช่น ใช้ binary search แต่ไม่บอกว่าข้อมูลต้องเรียง), 0 = วิธีไม่ต่ำกว่า O(n) หรือใช้ไม่ได้
- a2 (3): 3 = ระบุ threshold (เช่น 37.5 หรือ 38°C) และวิธีเปรียบเทียบชัดเจน, 1.5 = พูดกว้างๆ เช่น "เทียบกับอุณหภูมิที่กำหนด", 0 = ไม่มี
- a3 (3): 3 = ขั้นตอนครบตามลำดับ นำไปเขียนโค้ดได้, 1.5 = มีขั้นตอนแต่ข้ามบางส่วน, 0 = ไม่มีขั้นตอน
- c1 (2): 2 = นิยาม n ชัดเจน (และตัวแปรอื่นที่ใช้), 1 = ใช้ n แต่ไม่นิยาม, 0 = ไม่มี
- c2 (4): 4 = แจกแจงที่มาครบ (นับรอบ หรือ recurrence), 2 = มีร่องรอยการวิเคราะห์บางส่วน, 0 = เขียนแค่คำตอบ
- c3 (4): 4 = Big-O ถูกตามอัลกอริทึมที่เขียนและต่ำกว่า O(n), 0 = ผิด หรือไม่ต่ำกว่า O(n)
- ใช้ขั้นคะแนนตามที่ระบุข้างต้นเท่านั้น
- คำตอบที่ไม่เกี่ยวกับโจทย์ หรือว่าง ให้ 0 ทุกเกณฑ์
